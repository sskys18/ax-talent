카카오페이증권은 “자산 규모가 적거나 경험이 부족한 사용자도 소액으로 다양한 금융 상품에 접근할 수 있게 하는 투자 문화”를 지향한다고 설명합니다. 공식 서비스 소개에서도 카카오톡·카카오페이앱을 통한 쉬운 계좌 개설, 한 화면에 필요한 정보를 담은 MTS, 쉽게 이해할 수 있는 투자소식, 주식 모으기, 주식 선물하기, 해외 주식 소수점 거래, 시세 감지 주문, 종목별 토론방 등을 강조합니다. 
Kakao Pay Securities

성장 지표도 이 방향과 연결됩니다. 카카오페이증권은 2025년 6월 월간 거래자 수가 100만 명을 넘었고, MAU는 300만 명에 이른다고 밝혔습니다. 주식 거래자 수는 2024년 1월 16만 명에서 2025년 6월 72만 명으로 늘었고, 해외주식 거래자 수가 65만 명에 달해 글로벌 자산 투자 수요가 거래자 증가를 견인했다고 설명합니다. 
Kakao Pay Securities

AI 서비스도 이미 진행 중입니다. 카카오페이증권 주식봇은 카카오톡 팀채팅방에서 종목 시세, 뉴스, 기업 정보, 매출 정보, 종목토론방 요약 등을 제공하지만, 개인 투자 성향이나 위험 감수 능력을 고려하지 않은 종목 추천이나 직접 예측은 제공하지 않는다고 안내합니다.

무신사는 패션·뷰티 커머스에서 검색 중심 쇼핑을 발견 중심 쇼핑으로 바꾸는 것에 집중하고 있습니다. 2026년 AI 트렌드 큐레이션 도입 보도자료에서 무신사는 기존 이커머스 검색 환경이 명확한 구매 목적을 가진 목적형 소비자에게 편중되어 있었다고 보고, 목적 없이 최신 트렌드와 새로운 스타일을 탐색하는 “발견형 소비자”에 주목했다고 설명합니다. 이 서비스는 외부 비정형 트렌드 데이터를 수집·가공하고, 트렌드 키워드와 상품 속성을 자동 조합하는 AI 데이터 파이프라인을 사용합니다.

무신사의 2025년 실적도 이런 방향을 뒷받침합니다. 무신사는 2025년 연결 매출 1조4679억 원, 영업이익 1405억 원을 기록했고, 오프라인 채널 확대와 자체 브랜드 무신사 스탠다드 성장이 성과를 이끌었다고 발표했습니다. 또한 글로벌 시장에서는 일본, 중국 등에서 K-패션 브랜드의 해외 진출을 돕는 파트너 역할을 강화한다고 설명했습니다.

3-2. 무신사가 실제로 풀고 싶은 문제

무신사의 핵심 문제는 “추천을 잘하자”가 아닙니다. 이미 추천은 하고 있습니다. 진짜 문제는 더 앞단입니다.

무신사는 이미 AI 추천과 ChatGPT 앱을 하고 있으므로, 제출물은 소비자용 추천이 아니라 MD/파트너용 문제 해결 도구로 가야 합니다. 그래야 “아, 얘가 회사를 봤네”가 됩니다. 단순 쇼핑 챗봇은 그냥 디지털 마네킹입니다.

Same-less Style Analyst

아래 전체를 Codex에 붙여넣으세요.

너는 Codex 플러그인 개발자다.

목표:
무신사 상품·랭킹·리뷰 데이터를 기반으로 “무신사 냄새”가 나는 흔한 코디 위험도를 계산하고, 사용자가 피하고 싶은 스타일을 반영해 덜 겹치는 대체 코디 리포트를 생성하는 Codex 플러그인을 만들어라.

사용자는 Codex에게 로컬 CSV/JSON 파일을 분석하라고 시키고, Codex는 스크립트와 skill 지침을 이용해 Markdown/JSON/CSV 산출물을 생성해야 한다.

4. src/tools/clone_risk.py
Python 표준 라이브러리만 사용해서 작성한다.
pandas 같은 외부 라이브러리는 사용하지 말 것.

기능:
- products.csv, rankings.csv, reviews.csv, user_request.json을 읽는다.
- 각 상품에 대해 clone_risk_score를 0~100 사이로 계산한다.
- 점수 기준:
  - 랭킹이 높고 popularity_score가 높으면 위험 증가
  - review의 commonness_signal이 높으면 위험 증가
  - 사용자의 avoid 키워드와 tags/name/category/silhouette/color가 겹치면 위험 증가
  - black, gray, oversized, wide, basic, minimal 같은 흔한 조합 신호가 있으면 위험 증가
  - unique material, muted color, non-overfit silhouette, lower ranking 상품은 위험 감소
- 점수와 이유를 CSV로 저장한다.
- CLI로 실행 가능해야 한다.

CLI 예시:
python src/tools/clone_risk.py \
  --products src/examples/products.csv \
  --rankings src/examples/rankings.csv \
  --reviews src/examples/reviews.csv \
  --request src/examples/user_request.json \
  --out-dir src/outputs

출력:
src/outputs/clone_risk_scores.csv

5. src/tools/outfit_report.py
Python 표준 라이브러리만 사용해서 작성한다.

기능:
- clone_risk_scores.csv와 원본 상품 데이터를 읽는다.
- 사용자의 예산 안에서 3~5개 상품으로 대체 코디를 구성한다.
- 회피 키워드와 충돌하는 상품은 제외한다.
- clone_risk_score가 낮은 상품 위주로 추천하되, 카테고리 균형을 맞춘다.
  예: top, bottom, shoes, bag/accessory
- Markdown 리포트와 JSON 추천 결과를 생성한다.

CLI 예시:
python src/tools/outfit_report.py \
  --products src/examples/products.csv \
  --scores src/outputs/clone_risk_scores.csv \
  --request src/examples/user_request.json \
  --out-dir src/outputs

출력:
src/outputs/sameless_recommendations.md
src/outputs/recommendation.json

Markdown 리포트에는 다음 섹션을 포함한다:
# Same-less Style Analyst Report
## User Request
## Avoided Style Factors
## Clone Risk Summary
## Recommended Outfit
## Why This Is Less Common
## Budget Check
## Human Review Notes

6. src/tests/test_clone_risk.py
unittest 기반으로 작성한다.
테스트:
- clone_risk_score가 0~100 범위인지 확인

- 출력 파일이 생성되는지 확인
- 추천 결과 JSON에 avoided 키워드가 포함되지 않는지 확인

3. 삼일PwC 프롬프트
PBC Evidence Concierge

아래 전체를 Codex에 붙여넣으세요.

너는 Codex 플러그인 개발자다.

목표:
감사·세무·자문 과정의 PBC 자료요청 리스트를 해석하고, 로컬 증빙 폴더를 점검해 누락·부족·불일치 항목을 찾아낸 뒤, 제출 패키지 보고서와 추가 요청 메일을 생성하는 Codex 플러그인을 만들어라.

이 프로젝트는 회계 Q&A 챗봇이 아니다.
CFO 대시보드도 아니다.
자료요청과 증빙 제출 병목을 해결하는 Codex workflow plugin이다.

프로젝트 이름:
pbc-evidence-concierge

반드시 아래 구조로 만들어라:

.
├── src/
│   ├── .codex-plugin/
│   │   └── plugin.json
│   ├── skills/
│   │   └── pbc-evidence-concierge/
│   │       └── SKILL.md
│   ├── tools/
│   │   ├── pbc_matcher.py
│   │   └── report_writer.py

│       └── test_pbc_matcher.py
├── README.md
└── logs/
    └── README.md

요구사항:

1. src/.codex-plugin/plugin.json
- name: pbc-evidence-concierge
- version: 1.0.0
- description: PBC 자료요청을 증빙 체크리스트로 분해하고 로컬 증빙 파일의 제출 준비도를 검토하는 Codex workflow plugin
- skills 경로는 ./skills/ 로 지정한다.

2. src/skills/pbc-evidence-concierge/SKILL.md
반드시 포함할 내용:
- 이 skill은 감사·세무·자문 자료요청 검토 workflow임
- 일반 재무 대시보드나 회계 Q&A가 아님
- PBC는 Prepared By Client를 의미한다고 설명
- 입력:
  - pbc_requests.csv
  - evidence_manifest.csv
  - trial_balance.csv가 있으면 참고
- 출력:
  - outputs/pbc_evidence_review.md
  - outputs/missing_items.md
  - outputs/submission_package_manifest.json
  - outputs/followup_email_draft.md
- Codex가 수행해야 할 절차:
  1. PBC 요청 문장 읽기
  2. 요청 목적 추론
  3. 필요 증빙 분해
  4. 필수 연결키 도출
  5. evidence manifest와 매칭
  6. Ready / Partially ready / Missing / Needs human review로 분류
  7. 부족한 사유와 추가 요청 문안 생성
- 보수적으로 판단할 것
- 증빙을 조작하거나 있다고 가정하지 말 것
- 충분성이 애매하면 Needs human review로 표시할 것

4. src/tools/pbc_matcher.py
Python 표준 라이브러리만 사용한다.
pandas 사용 금지.

기능:
- pbc_requests.csv와 evidence_manifest.csv를 읽는다.
- request_text에서 요청 유형을 분류한다.
  예:
  - AR / receivables
  - cutoff
  - journal entry
  - inventory
  - related party
- 요청 유형별 required_evidence를 생성한다.
- 필수 연결키를 생성한다.
  예:
  - AR: customer_id, invoice_id, due_date, amount, receipt_date
  - cutoff: invoice_id, contract_id, shipment_date, revenue_date
  - JE: journal_id, preparer, reviewer, approval_date
  - inventory: item_id, aging_days, NRV, allowance_amount
  - related party: counterparty, contract_id, transaction_amount, terms
- evidence_manifest의 keywords, columns, period, entity를 기준으로 매칭한다.
- 각 요청을 다음 중 하나로 분류한다:
  - Ready
  - Partially ready
  - Missing
  - Needs human review
- 결과 JSON을 생성한다.

CLI 예시:
python src/tools/pbc_matcher.py \
  --requests src/examples/pbc_requests.csv \
  --evidence src/examples/evidence_manifest.csv \
  --trial-balance src/examples/trial_balance.csv \
  --out src/outputs/submission_package_manifest.json

코드가 만들어진 뒤, README를 보고 질문지 초안을 뽑을 때 쓰세요.

이 프로젝트의 README.md, src/.codex-plugin/plugin.json, src/skills/*/SKILL.md, tools 코드, examples, outputs를 읽고 제출용 질문 5문항 답변 초안을 작성해줘.
